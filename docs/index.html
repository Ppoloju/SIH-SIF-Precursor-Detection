01 · The Problem

Small reports can hide catastrophic potential

OIL collects large volumes of UA/UC observations, near-misses and incidents through its HSSE platform — mostly free text. Traditional review classifies reports by what actually happened; a minor-outcome near-miss can still describe conditions that could have caused a serious injury or fatality.

What happened?

"Worker started maintenance without isolating energy."

Actual outcome: no injury — the job was stopped in time.

What could have happened?

"Uncontrolled energy release while a worker is on the line."

Potential outcome: serious injury or fatality.

Core question: which reports carry genuine SIF potential, why (with quoted evidence), and where does the same precursor keep recurring? This prototype screens every report the moment it arrives and lets HSE experts focus where fatal potential is highest. It is an early-warning decision-support layer — it does not replace OIL's HSE process or experts.

Plain-language summary

Three parts for every report — What happened · Why it matters · Next step — readable by any supervisor, not just a data team.

Suggested corrective actions

A concrete checklist built from the rule profile and failed barriers (verify gas testing, reinstate standby, brief the crew, escalate if HIGH).

One report can touch several rules. Detection is multi-label; the engine reports the primary Life-Saving Rule and every matched signal. Example: an entry without gas testing maps to Confined Space Entry and flags Toxic Gas Safety when H₂S vocabulary appears.

05 · How the AI Works

A hybrid pipeline, not "just an LLM"

Safety screening must work even when no LLM is available. Each stage uses the most reliable, explainable tool for the job.

1
Deterministic rules — always on negation-aware indicator detection with literal evidence (isolation, LOTO, gas testing, fall protection, permits…)
2
Multilingual layer Hindi, Bengali, Assamese — Devanagari/Bengali script and romanised text map to the same rules, evidence stays in the original words
3
Extraction + scoring hazard, barrier failure, activity, equipment; transparent priority factors (indicators + severity + exposure + barrier)
4
Similarity engine token overlap + shared rule / hazard / barrier / activity — works across languages, no external model needed
5
Optional LLM refinement — validated, with fallback Llama via Groq may rephrase explanations into the report's language; on any failure the deterministic result stands
6
Feedback → retraining learned signals from HSE-reviewed labels tune confidence and evidence on future analyses (model tag rules-v1+tuned); a learned keyword alone never flips a verdict

The ten Life-Saving Rules the engine maps to

Work Authorization Energy Isolation Bypassing Safety Controls Confined Space Entry Working at Height Safe Mechanical Lifting Toxic Gas Safety Driving Safety Line of Fire Hot Work Safety

Why not just an LLM?

Cost, latency and unpredictability make an LLM-only engine unsuitable for safety screening. Rules + multilingual lexicons answer instantly and explainably; the LLM only polishes complex interpretation.

Language coverage

Sample phrases the engine already reads: gas test nahi, गैस टेस्ट के बिना, গ্যাস টেস্ট করা হয়নি, গেছ টেষ্ট নকৰাকৈ, harness chara — each one flags the right rule with literal evidence.

Honest by design

"Not specified" instead of guessing; uncertainty notes surface honestly; controlled work (isolated, tested, guarded) never produces a false alarm.

06 · Evaluation

Measured, not just demoed

The engine is held against a hand-labeled golden set of 35 reports — English, Hindi, Bengali and Assamese — with a live Evaluation page and CLI. Runs deterministically in ~35 ms.

35 / 35SIF verdicts correct
1.000Precision · Recall · F1
19 / 19Multilingual cases
0 / 0False positives / negatives

What is measured

  • SIF classification — precision, recall, F1, confusion matrix
  • Per Life-Saving-Rule mapping — every one of the ten rules, multi-label
  • Language coverage — English, Hindi, Bengali, Assamese (native + roman)
  • Human agreement — reviewed labels vs the AI, recomputed on every "Train" run

Honesty: these numbers describe the deterministic rules on the in-repo reference set. No accuracy on real OIL data is claimed until HSE-validated labels exist. Recall matters most — missing a real precursor is worse than an extra alert.

Human-in-the-loop

  • HSE experts confirm, reject or correct every AI flag — with full context (evidence, summary, similar reports)
  • Review decisions are stored as labeled examples in the database
  • "Train on reviewed labels" re-measures agreement and learns signal phrases from the disagreements
  • Learned signals are quoted and flagged on future analyses — verdicts never auto-flip
Limitations are stated, not hidden: misspellings and local jargon can reduce detection; the priority model and rule taxonomy are prototype-level and require OIL/HSE validation; results are decision support.

08 · Run & Roadmap

Turn it on, point it at your dataset

The application starts empty (SEED_DEMO_DATA=0) so you can verify it against your own reports. Full run instructions live in the repository README.

# 1 · database (optional — SQLite fallback exists)
docker compose up -d

# 2 · backend
cd backend && pip install -r requirements.txt
uvicorn app.main:app --port 8000        # creates schema; empty DB stays empty

# 3 · frontend
cd frontend && npm install && npm run dev   # http://127.0.0.1:3000
Import your data: open Import Data, upload any CSV / Excel / JSON export (or paste JSON) — watch the job progress bar, then explore Reports, Dashboard, Rules, Sites, Activities, Barriers, Patterns and Evaluation. Want the 45 labeled demo reports back? Set SEED_DEMO_DATA=1 and restart.
